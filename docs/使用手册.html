1. 项目是什么

面向刺绣公司的私有化本地离线智能客服 Agent：本地 LLM 推理 + RAG 知识库 + 双角色客服（C 端客户顾问 / B 端员工助手），全程无公网调用。

┌─ 前端    网页（客户咨询页 / 员工工作台 双入口）
├─ 后端    FastAPI（角色路由 + SSE 流式 + 工单查询）
├─ Agent   意图分类 → 需求追问循环 → 工单自动创建
├─ 检索    BM25 + FAISS 向量 + bge-reranker 精排 + 角色权限过滤
├─ 模型    Ollama 本地推理（OpenAI 兼容接口）
└─ 数据    知识库（公开/内部分库）+ SQLite 工单 + FAISS 索引

双角色核心逻辑：

  • C 端客户：只能访问 data/knowledge/（公开知识），问价格/工期等门店专属信息 → 固定话术转人工 + 自动建工单。
  • B 端员工：可访问公开 + data/internal/（内部知识），支持行业答疑、对话复盘、文案生成。

2. 快速开始（5 分钟跑起来）

2.1 环境要求

组件 版本要求 说明
Python 3.10+（本机 3.11.9） 后端运行环境
Ollama 0.3x+（本机 0.32.4） 本地模型推理服务
模型 qwen2.5:7b-instruct + bge-m3 已在本机拉取
显存 8GB（7B Q4 量化约 4.5GB） 无 GPU 可降级 3B

2.2 一键启动

cd D:\embroidery_agent
.\start.ps1

脚本自动做三件事：

  1. 检查 Ollama 是否运行、模型是否就绪（未就绪给出提示，并降级为"知识库直接引用"模式）；
  2. 检查知识库索引是否存在，不存在则自动构建；
  3. 启动 uvicorn 服务。

浏览器打开 http://127.0.0.1:8000。

2.3 手动启动（等价命令）

cd D:\embroidery_agent
$env:PYTHONPATH = "src"
uvicorn embroidery_agent.api.server:app --host 127.0.0.1 --port 8000

注意：每次打开新的 PowerShell 窗口都要重新设置 $env:PYTHONPATH = "src"，否则会报 ModuleNotFoundError。

3. 对接本地模型（核心）

3.1 模型架构（谁负责什么）

角色 模型 用途
对话/生成 qwen2.5:7b-instruct 回答生成、意图判断、需求表单提取、文案/复盘
Embedding bge-m3 把知识库文本和用户问题转成向量（检索用）
Reranker（可选） BAAI/bge-reranker-base 检索结果精排（本地未下载则自动跳过）

3.2 对接步骤（Ollama）

第 1 步：安装并启动 Ollama

  • 下载安装：https://ollama.com （Windows 原生安装包）
  • 启动：开始菜单搜索 "Ollama" 打开，或命令行运行 ollama serve

第 2 步：拉取模型（一次即可，离线后无需再下载）

ollama pull qwen2.5:7b-instruct    # 对话模型（8GB 显存推荐）
ollama pull bge-m3                 # Embedding 模型

显存不足 8GB：改用 ollama pull qwen2.5:3b-instruct，并把配置里的 chat_model 改掉。 纯 CPU：用 3B 或 1.5B，速度较慢但可用。

第 3 步：验证 Ollama 就绪

ollama list        # 应看到已拉取的模型

第 4 步：确认项目配置指向正确（默认已指向，一般无需改）：

查看 configs/default.json 的 llm 段：

"llm": {
  "base_url": "http://127.0.0.1:11434/v1",   ← Ollama 的 OpenAI 兼容接口地址
  "chat_model": "qwen2.5:7b-instruct",        ← 对话模型名（必须与 ollama list 一致）
  "embedding_model": "bge-m3"                 ← Embedding 模型名
}

3.3 对接"微调后的模型"（LlamaFactory 产物）

微调完的 LoRA 模型导出为 GGUF 后，用 Ollama 导入，然后只需改一行配置：

# 在 Ollama 中创建自定义模型（MODELFILE 指向微调产物的 GGUF 文件）
ollama create zhixiufang-custom -f ./finetune/Modelfile
# 验证
ollama list   # 应看到 zhixiufang-custom

然后把 configs/default.json 的 llm.chat_model 改为：

"chat_model": "zhixiufang-custom"

重启服务即生效。业务代码零改动——这就是"应用层与推理层解耦"设计的好处（所有模型调用都走 OpenAI 兼容接口）。

微调数据准备见 第 8 节。

3.4 模型不可用时的降级

  • Ollama 未启动：/api/v1/status 显示 llm_ready: false；回答退化为"知识库直接引用"（抽取式回答），检索链路仍可用。
  • bge-m3 未拉取：构建知识库时向量索引失败，自动降级为仅 BM25 检索（build_kb.py 输出 vector_ok: false）。
  • reranker 未下载：自动跳过精排（离线优先，避免联网卡死）。

4. 配置文件详解

4.1 configs/default.json（唯一需要手动改的配置）

{
  "llm": {                                    ← 本地模型对接
    "base_url": "http://127.0.0.1:11434/v1",  ← Ollama OpenAI 兼容接口（一般不动）
    "chat_model": "qwen2.5:7b-instruct",      ← ★ 对话模型名（换微调模型改这里）
    "embedding_model": "bge-m3",              ← ★ Embedding 模型名
    "timeout_seconds": 120                    ← 模型响应超时（秒）
  },
  "rerank": {
    "enabled": true,                          ← 是否启用重排
    "model_name": "BAAI/bge-reranker-base",   ← reranker 模型（未下载自动跳过）
    "device": "cpu"                           ← 运行设备（cpu/gpu）
  },
  "retrieval": {
    "recall_k": 20,                           ← 召回数量（BM25+向量各召回多少）
    "top_k": 5,                               ← 最终返回给 LLM 的命中数
    "min_score": 0.2,                         ← 最低分数阈值
    "use_vector": true,                       ← 是否启用向量检索
    "use_bm25": true,                         ← 是否启用 BM25
    "use_rerank": true                        ← 是否启用精排
  },
  "kb": {
    "public_path": "data/knowledge",          ← 公开知识库目录（客户+员工可见）
    "internal_path": "data/internal",         ← 内部知识库目录（仅员工可见）
    "index_path": "data/index",               ← 索引保存位置
    "chunk_size": 300,                        ← 切块长度（字符）
    "chunk_overlap": 40                       ← 切块重叠
  },
  "storage": {
    "db_path": "data/embroidery.db"           ← 工单 SQLite 数据库
  },
  "tickets": {
    "auto_create": true                       ← 是否自动创建工单
  }
}

所有路径都是相对项目根目录的。configs/default.json 中改模型名/路径后无需重新构建，重启服务即可（知识库索引只在 build_kb.py 时构建）。

4.2 环境变量（core/settings.py 支持，一般不强制）

Settings 类支持从环境变量覆盖配置，字段名大写（如 OLLAMA_BASE_URL、LLM_MODEL）。绝大多数情况不需要设置环境变量，直接改 default.json 更直观。

6. 一次对话的完整链路

以客户输入"我想定制一幅绣品送长辈"为例：

  1. 前端 app.js 发送 POST 到 /api/v1/customer/chat（带 session_id，同会话多轮）。
  2. API server.py 收到请求，交给 CustomerAgent.process()。
  3. 拦截门店专属：若问题含"价格/工期/多少钱"等词 → 直接返回兜底话术 + 创建工单，不查知识库。
  4. 意图分类 intent.py 识别为 CUSTOM_REQUIREMENT（定制需求）。
  5. 需求追问循环 customer.py：
    • LLM 从对话中提取需求字段（answer.py → extract_requirement_form，JSON 结构化输出）；
    • 若缺字段 → 按固定顺序只追问 1 个（主题→尺寸→工艺→用途→预算→交付→特殊要求）；
    • 若齐全 → 输出【结构化需求表单】+【适配方案建议】+【待人工确认】，并自动建工单。
  6. 回答经 SSE 流式返回前端逐字显示。
  7. 工单写入 data/embroidery.db，前端工单栏轮询 /api/v1/tickets 显示。

客户问"苏绣和湘绣有什么区别"（知识咨询）时： 1-2 同上 → 3 无价格词 → 4 意图为 KNOWLEDGE → 5 HybridRetriever 混合检索（BM25+向量+可选精排）→ 6 拼装 RAG 上下文 → 7 LLM 基于知识库回答并标注来源 → 8 SSE 返回。

7. 知识库管理（扩充/重建/权限）

7.1 扩充知识库（推荐做法）

  1. 在 data/knowledge/ 新建 .md 文件（或 .txt），文件名即分类名（如 苏绣.md、装裱.md）。
  2. 内容建议按段落/小节组织（# 标题 + 段落），系统会按段落优先自动切块（chunk_size=300，超长段落自动截断）。
  3. 员工专属内容放 data/internal/（客户检索不到）。

文件命名即分类：工艺.md、针法.md、品类.md、保养.md、纹样寓意.md 是示例；新增文件会自动成为新分类。

7.2 重建索引（每次改完知识库后必须执行）

cd D:\embroidery_agent
$env:PYTHONPATH = "src"
python scripts/build_kb.py

输出示例：

{ "public_chunks": 11, "internal_chunks": 2, "total_chunks": 13,
  "dimension": 1024, "vector_ok": true, "warning": null }
  • vector_ok: true 表示向量索引成功（bge-m3 可用）；
  • vector_ok: false + warning 表示 Ollama/bge-m3 不可用，降级为仅 BM25。

7.3 权限隔离（系统自动，无需配置）

目录 可见角色
data/knowledge/ 客户 + 员工
data/internal/ 仅员工

检索时 HybridRetriever.search(query, role=...) 按角色过滤 chunk 的 visibility，这是最硬的权限边界（代码层过滤，不依赖提示词）。

8. 微调流程（LlamaFactory 对接）

8.1 数据准备

  1. 在 data/finetune/ 维护 4 类原始数据（JSONL，已有示例）：
    • raw_qa.jsonl：单轮客服问答（instruction + answer）
    • raw_dialogue.jsonl：多轮对话（conversations 数组，user/assistant 交替）
    • raw_staff.jsonl：员工侧（复盘/文案/拆单）
    • raw_form.jsonl：需求表单结构化（instruction + form JSON）
  2. 导出 LlamaFactory 训练集：
python scripts/export_finetune.py
# 生成 data/dataset.jsonl（alpaca 格式：instruction/input/output/system/history）

8.2 LlamaFactory 训练

  • 克隆/安装 LLaMA-Factory（74.5k star）；
  • 用其 Web UI（LlamaBoard）或 CLI，加载 data/dataset.jsonl；
  • 参数建议（8GB 显存方案）：
    • 基座模型：Qwen2.5-7B-Instruct
    • 方法：lora（或 qlora，4bit 量化）
    • lora_rank=8，lora_alpha=16
    • 训练轮数 num_train_epochs=3（数据量小）
  • 训练完导出：
    • 合并权重 → 导出 GGUF → 生成 Modelfile → ollama create zhixiufang-custom
    • 或直接导出 Ollama modelfile（LlamaFactory 支持一键导出）

8.3 接入

改 configs/default.json 一行：

"chat_model": "zhixiufang-custom"

重启服务。前端、检索、工单逻辑全部零改动。

9. 评测

cd D:\embroidery_agent
$env:PYTHONPATH = "src"
python scripts/evaluate.py
  • 读 data/golden_test.jsonl（每行：{"query": "...", "expected_sources": ["工艺"], "role": "customer"}）；
  • 计算 Hit@1 / Hit@5 / MRR@K（客户与员工各跑一遍）；
  • 输出样例：查询命中的来源文件名及排序。

扩充黄金测试集：在 data/golden_test.jsonl 追加行即可，越多越能反映真实效果。每次改知识库或换模型后重跑，作为效果回归依据。

10. 前端使用说明

  • 打开 http://127.0.0.1:8000 ；
  • 右上角切换客户咨询 / 员工工作台（角色决定知识库权限和话术）；
  • 聊天框：Enter 发送，Shift+Enter 换行；
  • 右侧栏：系统状态（LLM 就绪/知识库块数）+ 待跟进工单（10 秒自动刷新）；
  • 提示语"本地离线运行 · 行业知识仅供参考"为固定展示。

11. 常见问题排查

ModuleNotFoundError: No module named 'fastapi'/'faiss' 依赖没装 pip install -e ".[api,retrieval]"
页面打开但回答是"知识库直接引用"风格 Ollama 未启动 启动 Ollama，ollama list 确认模型存在

12. 安全与生产化加固（v1.1 新增）

12.1 员工口令三档配置（按安全性递增）

方式 配置位置 适用
明文口令 configs/default.json → staff.passcode 本地开发演示
口令哈希（推荐） staff.passcode_sha256（删除明文字段） 单机生产
环境变量注入 EMBROIDERY_STAFF_PASSCODE（优先级最高） 服务器部署

生成哈希：python scripts/hash_passcode.py 你的口令，把输出填入 passcode_sha256 并删除明文 passcode 字段。员工登录时仍输入原口令，服务端只比对哈希。

12.2 速率限制

configs/default.json 的 rate_limit 段：默认每个 IP 每分钟 10 次对话 / 30 次检索，超限返回 429 与友好提示。可通过 chat_per_minute / search_per_minute 调整，enabled: false 关闭。注意：这是单进程限流，多实例部署需换共享存储方案。

12.3 提示词注入防御

  • 规则层：nlp/guard.py 识别"忽略指令/越狱/套取系统提示/套取内部底价"等话术，命中即礼貌拒绝并记入日志（logs/app.log 搜 prompt_injection_blocked）。
  • 提示词层：客户/员工 system prompt 均有"安全防线（最高优先级）"条款。
  • 新增注入模式：在 guard.py 的 _INJECTION_PATTERNS 里加正则即可，配套测试在 tests/test_guard.py。

12.4 知识库自动重建索引

无需手动跑 build_kb.py：服务每次处理请求前会比对 data/index/manifest.json（记录每个源文件的 mtime+size+embedding 模型名），发现文件变更自动重建。手动强制重建仍可用 POST /api/v1/kb/build（需员工口令）。

12.5 降级告警（不再静默）

以下情况会写入 logs/app.log（级别 WARNING），方便排查"为什么回答变简单了"：

  • llm_fallback reason=llm_not_ready：Ollama 未启动或 模型被删除（is_ready 现在会检查模型是否存在）；
  • llm_fallback reason=stream_error：生成中报错；
  • vector_search_failed：向量检索失败，当次降级为 BM25。

诊断模型状态：/api/v1/status（员工口令）的 llm_ready 即真实模型可用性。

12.6 数据飞轮（真实对话 → 微调数据）

python scripts/export_conversations.py   # 从 SQLite 导出真实问答对 → data/finetune/candidates.jsonl

候选数据带 reviewed: false 标记；人工逐条审核后合并进 raw_qa.jsonl，再跑 export_finetune.py 生成训练集。固定话术/占位符自动过滤。
